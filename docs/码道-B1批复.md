## 二、需要收敛的五处

**1. 取消 RelayCommand。**
不做严格 MVVM。菜单项继续用 Click 事件 + 直接调方法，不引入 ICommand、不做命令绑定。

**2. TrayCoordinator 并入 TrayIconHost。**
它只有「UI 线程调度 + 订阅三个事件」这点职责，单独成类会让「状态变更 → 刷新菜单」多绕一层。
合并后由 TrayIconHost 暴露 `OnAutoSwitched(object?, AutoSwitchEventArgs)` 与
`OnServiceError(object?, Exception)` 两个方法，供 App 订阅时直接挂上去。

**3. 不引入 IHotkeyStatusSource。**
保留 `App.HotkeyStatus` 这个静态属性不变（PreferencesWindow 与 SettingsWindow 一行都不改）。
App 内部存一个 `private static HotkeyService? _hotkeyService`，属性改为转发：

```
public static IReadOnlyDictionary<string, bool> HotkeyStatus
    => _hotkeyService?.Status ?? EmptyStatus;   // EmptyStatus 为静态空只读字典
```

这样窗口侧的静态访问路径不变，注册结果仍然是实时的（不是启动快照）。

**4. 不引入 IUiDispatcher。**
VM 与服务里需要切 UI 线程时直接用 `Application.Current.Dispatcher`，与现状一致。
不要在服务里缓存 Dispatcher 的副本。

**5. IntegrityGuard 并入 DiagnosticsService。**
30 行的完整性检查本质上属于「启动诊断」，合并后少一个类。
但**调用位置必须保持**：仍在 `OnStartup` 最前、`base.OnStartup(e)` 之前、UI 线程上，
`MICSWITCHER_NO_INTEGRITY_WARN=1` 的跳过逻辑与提示文案都不变。

收敛后目标类共 9 个：

```
NativeMethods
DiagnosticsService        （含完整性检查、日志、环境探测）
SingleInstanceService
HotkeyService
TrayIconHost              （含图标、菜单构建、气泡、事件订阅）
TrayCommands              （模式切换、切设备、轮换、静音、开机自启）
SettingsWindowCoordinator
ShutdownCoordinator
AppBootstrapper
```

## 三、补一条你风险清单里没有的

**HotkeyService 持有 HwndSource，Dispose 必须在创建它的 UI 线程上执行。**
跨线程 Dispose 可能抛异常或泄漏窗口句柄。

请在 HotkeyService 内部记录创建时的线程 id；`Dispose()` 时若当前线程不是它，
用 `Application.Current.Dispatcher.Invoke` 调度过去（Dispatcher 已关闭时吞异常并写一行日志）。
这一条要写进实现，不要留给后面运行时才发现。
