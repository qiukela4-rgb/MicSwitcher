## 二、批次 2 遗留一个需要加固的点

`ReloadIfChanged()` 会先 `Unregister()` 再 `Register()`，而 `Register()` 在**当前线程**
创建 HwndSource。当前唯一调用点是 `ApplyConfig`（UI 线程），所以安全；
但将来若有人从后台线程调用，`new HwndSource` 会在没有 Dispatcher 的线程执行，直接抛异常。

请在 `Register()` 开头补一句防御：

```csharp
if (Application.Current?.Dispatcher is null || !Application.Current.Dispatcher.CheckAccess())
{
    DiagnosticsService.Log("热键：Register 在非 UI 线程被调用，已忽略");
    return;
}
```

UI 线程下 `CheckAccess()` 为 true，现有行为不变；只在错用时留痕。

## 三、批次 3：SingleInstanceService

搬移范围按你的清单：`_singleInstanceMutex` / `_showSettingsEvent`（20–21）、
OnStartup 的单实例块（50–89）、`SignalExistingInstance`（759–776）、
`ActivateExistingWindow`（794–815）、常量（787–788）、`StartShowSettingsListener`（817–837）。

**四条硬约束：**

1. **命名对象仍在 OnStartup 主线程创建。** Mutex 与 EventWaitHandle 的会话命名空间和 ACL
   取决于创建时的会话；搬到构造函数或线程池会改变语义。
2. **`Local\` 前缀不许改。** 改 `Global\` 在普通权限下会 Access denied。
3. **listener 的 WaitOne 与 Dispose 竞争要保留现有容错。** 原代码在 `ObjectDisposedException`
   时 `catch { return; }` 退出线程；搬移时不要把它简化成裸 `catch`，也不要让异常冒到线程外
   （那会变成未处理异常）。
4. **置前窗口的手段不变。** `SetForegroundWindow` 受前台锁限制，现有代码怎么绕的就怎么保留
   （附到前台输入线程 / `AllowSetForegroundWindow` 之类），不要"优化"成直接 `Activate()`。
