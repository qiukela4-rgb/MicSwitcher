## 四、任务 B：MVVM 拆分（前置已就绪，可以开始）

**前置条件已满足**：`smoke.cmd` 能在每次改完 UI 后确认「起得来、托盘建了、不闪退」；
`test.cmd` 有 103 个用例保护 Core 逻辑。这两条是拆 UI 的安全网。

**分批原则**：一批只动一个窗口。每批结束必须依次跑通
`build.cmd` → `test.cmd` → `smoke.cmd`，任一失败就回退这一批，
不要连着改两个窗口再一起验。

| 批次 | 目标 | 不许动 |
|---|---|---|
| B1 | `App.xaml.cs`（864 行）拆出：托盘菜单构建 / 单实例 / 热键注册 / 退出流程 | 菜单项文案与顺序；单实例的 `Local\` 前缀；退出时的 3 秒超时兜底 |
| B2 | `SettingsWindow.xaml.cs`（851 行）拆出设备列表、拖拽排序、主窗口逻辑 | 拖拽手感参数（Popup 复用、210ms 缓动、插入线光晕） |
| B3 | `PreferencesWindow.xaml.cs`（733 行）拆出六个设置分区 | 任何默认值（`SilenceThreshold=0.004`、`DebounceSamples=3` 等） |

**每批的汇报格式**：

```
改动文件：（新增/修改，逐条）
新增类与职责：（一句话说清每个新类管什么）
build.cmd 输出：（逐字）
test.cmd 输出：（逐字，含总数/通过/失败）
smoke.cmd 输出：（逐字）
只能靠肉眼验证的行为：（列出来，不要含糊成「一切正常」）
```

**特别提醒**：这一层没有任何自动化 UI 测试，`smoke.cmd` 只验证「能启动」。
所以每次改动要**尽量小步**，把「需要人眼确认的项」明确列出来，别攒成一大坨。
